# Отчёт по мастерам (Report Builder)

Веб-сервис для загрузки Excel-файла с заказами, валидации данных и формирования сводного отчёта по каждому мастеру.

## Структура проекта

```
.
├── app.py # Создание экземпляра FastAPI и подключение роутеров
├── main.py # Точка входа для запуска uvicorn
├── templates/
│ └── index.html # HTML-форма для загрузки файла
├── routers/
│ ├── __init__.py
│ ├── report.py # Роутер с эндпоинтами (GET /, POST /, /download)
│ └── message.py # Функция отправки уведомлений в Telegram
├── report/ # Пакет с бизнес-логикой
│ ├── __init__.py
│ ├── handler.py # Чтение Excel-файла
│ ├── normalization.py # Нормализация сырых данных
│ ├── validation.py # Валидация нормализованных данных
│ ├── models.py # Датаклассы ReportOrder и ValidationError
│ └── report_build.py # Построение отчёта и сохранение в Excel
├── .env # Переменные окружения (TELEGRAM_BOT_TOKEN)
├── app.log # Лог-файл
└── requirements.txt
```

## Инструкция по запуску

1. **Клонируйте репозиторий и перейдите в папку проекта:**

```bash
cd test_task
```

2. **Создайте и активируйте виртуальное окружение:**

```bash
python -m venv .venv
source .venv/bin/activate # Linux/Mac
.venv\Scripts\activate # Windows
```

3. **Установите зависимости:**

```bash
pip install -r requirements.txt
```

4. **Создайте файл `.env` с токеном Telegram-бота:**

```
TELEGRAM_BOT_TOKEN=...
```

5. **Запустите сервер:**

```bash
python main.py
```

Или напрямую:

```bash
uvicorn app:app --host 0.0.0.0 --port 8000 --reload
```

6. **Откройте браузер:** `http://localhost:8000`

## Как работает проект

### Общая схема обработки

1. Пользователь загружает Excel-файл через веб-интерфейс.
2. Файл сохраняется на сервере.
3. Данные проходят нормализацию, затем валидацию.
4. Валидные заказы агрегируются по мастерам.
5. Формируется Excel-файл с двумя листами: «Отчёт по мастерам» и «Ошибки».
6. Пользователь получает ссылку на скачивание готового отчёта.
7. отправляется уведомление о готовности отчёта ботом на указанный ID.

### Нормализация данных

**Цель:** привести все данные к единому, предсказуемому формату, устойчивому к «грязным» входным данным.

**Что нормализуется:**

| Поле | Правило |
|------|---------|
| **Город** | Точное совпадение с эталонным списком или нечёткий поиск (thefuzz). Неизвестный город → `None`. |
| **Мастер** | Удаление лишних пробелов, приведение к формату «Фамилия Имя» с заглавных букв. Пустое значение → `None`. |
| **Статус заказа** | Синонимы приводятся к каноническим «Выполнен» или «Отменен». Неизвестный статус сохраняется как есть (для последующей фильтрации). |
| **Дата** | Приведение к формату `%d.%m.%Y` из множества возможных форматов. Поддерживаются разделители (`.`, `-`, `/`), двузначный год, текстовые даты с русскими названиями месяцев. Неудачное распознавание → `None`. |
| **Сумма** | Удаление валютных символов, пробелов. Замена запятой на точку. Отрицательные значения приводятся к положительным (по модулю). Преобразование в `Decimal`.   Нечисловые значения → `None`. |
| **Рекламация / Фото** | `да/yes/1/true` → `True`, `нет/no/0/false` → `False`. Остальное → `None`. |

### Валидация данных

**Цель:** отфильтровать строки, которые невозможно корректно обработать.

**Проверки:**

| Правило | Действие |
|---------|----------|
| Все обязательные поля (`id`, `date`, `city`, `master`, `status`, `amount`, `complaint`, `photo`) должны быть не `None` | Отсутствующее поле → ошибка, строка исключается |
| Дата должна быть реальной (30.02.2026, 31.04.2026 и т.п. отбрасываются) | Невалидная дата → ошибка |
| ID заказа должен быть уникальным (первый встреченный считается валидным) | Дубликат → ошибка |
| Статус должен быть «Выполнен» или «Отменен» | Другие статусы («Новый», «В работе», «Перенесен») → строка игнорируется без ошибки |

### Построение отчёта

**Метрики для каждого мастера (только по выполненным и отменённым заказам):**

- Количество выполненных заказов
- Сумма выполненных заказов
- Количество рекламаций
- Процент рекламаций (от выполненных)
- Количество заказов без фото
- Количество отменённых заказов

**Итоговый Excel-файл содержит:**

- Лист «Отчёт по мастерам» — сводная таблица с метриками.
- Лист «Ошибки» — строки, исключённые из обработки, с указанием номера строки, ID заказа, поля и сообщения об ошибке.

### Логирование

Все ключевые события записываются в `app.log`:

- Загрузка файла
- Начало и завершение валидации
- Предупреждения о нераспознанных статусах, датах, суммах
- Исключённые строки с указанием причины
- Отправка Telegram-уведомлений

## Принятые решения и спорные моменты

| Решение | Обоснование |
|---------|-------------|
| **Нормализатор не валидирует** | Нормализатор только приводит к единому виду, но не проверяет корректность. Это позволяет чётко разделить ответственность: нормализатор — «чистильщик», валидатор — «контролёр». |
| **Некорректные даты в ошибки** | Только календарно несуществующие даты (32.05.2026, 30.02.2026) считаются ошибкой. Даты с другими разделителями или текстовые успешно нормализуются. |
| **Игнорирование «нецелевых» статусов** | Статусы «Новый», «В работе», «Перенесен» не включаются в отчёт и не считаются ошибкой, т.к. по условию задания нужны только выполненные и отменённые заказы. |
| **Дубликаты ID исключаются** | Первая строка с ID считается валидной, все последующие — дубликатами и попадают в ошибки. Это позволяет сохранить хотя бы один экземпляр заказа. |
| **Опциональные поля `contractor`, `service_type`, `source`** | Они не обязательны для отчёта, поэтому отсутствующие значения заменяются пустой строкой. |
| **Суммы с запятой** | Запятая интерпретируется как десятичный разделитель (российский стандарт), поэтому `"10500,50"` корректно преобразуется в `Decimal("10500.50")`. |
| **Отрицательные суммы** | Знак минуса удаляется при нормализации, сумма всегда становится положительной. Считаем, что отрицательная сумма — опечатка ввода. |
| **Нечёткий поиск городов** | Опечатки («Новоросийск», «Краснадар») исправляются с помощью библиотеки `thefuzz` с порогом схожести 80%. |
| **Telegram-уведомления** | Отправляются в фоновом режиме через `BackgroundTasks`, не задерживая ответ пользователю. Если токен не задан или ID не указан — уведомления молча пропускаются. |
